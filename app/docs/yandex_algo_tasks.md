# Yandex Interview Tasks: разбор паттернов


Формат:
- `Источник` - откуда задача.
- `Что спрашивают` - нормальная формулировка задачи.
- `Идея` - как думать на собесе.
- `Сложность` - время и память в `O(...)`.
- `Ловушки` - где чаще ошибаются.

## 1. Merge Intervals

Источник: https://leetcode.com/problems/merge-intervals/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Дан массив интервалов `[start, end]`. Нужно объединить все пересекающиеся интервалы и вернуть список непересекающихся интервалов.

Пример:

```python
intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]
# result: [[1, 6], [8, 10], [15, 18]]
```

### Идея

Сначала интервалы нужно отсортировать по началу. После этого пересекающиеся интервалы окажутся рядом.

Дальше идешь по интервалам слева направо:
- если ответ пустой, добавляешь первый интервал;
- если начало текущего интервала меньше или равно концу последнего интервала в ответе, значит они пересекаются;
- тогда обновляешь конец последнего интервала: `max(old_end, current_end)`;
- если не пересекаются, добавляешь текущий интервал как новый.

### Сложность

Время:

```text
O(n log n)
```

Потому что нужна сортировка.

Память:

```text
O(n)
```

Если считать массив ответа. Если разрешено менять входной массив, дополнительная память может быть меньше, но ответ все равно хранится.

### Ловушки

- Делать двойной цикл и сравнивать каждый интервал с каждым: это `O(n^2)`.
- Не учитывать случай, когда интервалы касаются: `[1, 4]` и `[4, 5]` обычно объединяются в `[1, 5]`.
- Забыть отсортировать интервалы.

## 2. Merge Sorted Array

Источник: https://leetcode.com/problems/merge-sorted-array/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Даны два отсортированных массива `nums1` и `nums2`. В `nums1` есть место в конце под элементы второго массива. Нужно слить массивы так, чтобы `nums1` стал отсортированным.

Пример:

```python
nums1 = [1, 2, 3, 0, 0, 0]
m = 3
nums2 = [2, 5, 6]
n = 3
# nums1 после решения: [1, 2, 2, 3, 5, 6]
```

### Идея

Идти нужно с конца, а не с начала.

Держишь три указателя:
- `i = m - 1` - последний настоящий элемент в `nums1`;
- `j = n - 1` - последний элемент в `nums2`;
- `k = m + n - 1` - позиция, куда ставим следующий максимальный элемент.

На каждом шаге сравниваешь `nums1[i]` и `nums2[j]`, больший ставишь в `nums1[k]`, потом двигаешь указатели.

### Сложность

Время:

```text
O(m + n)
```

Память:

```text
O(1)
```

Потому что результат пишется прямо в `nums1`.

### Ловушки

- Идти слева направо и затирать еще не обработанные элементы `nums1`.
- Забыть дописать остаток `nums2`.
- Делать `sorted(nums1[:m] + nums2)`, если от тебя ждут in-place решение.

## 3. Reverse Linked List

Источник: https://leetcode.com/problems/reverse-linked-list/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Дана голова односвязного списка. Нужно развернуть список и вернуть новую голову.

Пример:

```text
1 -> 2 -> 3 -> 4 -> None

result:
4 -> 3 -> 2 -> 1 -> None
```

### Идея

Нужно менять ссылки `next` у узлов.

Держишь:
- `prev` - предыдущий узел, сначала `None`;
- `current` - текущий узел;
- `next_node` - временно сохраняет следующий узел, чтобы не потерять остаток списка.

На каждом шаге:
- сохраняешь `next_node = current.next`;
- разворачиваешь ссылку: `current.next = prev`;
- двигаешь `prev = current`;
- двигаешь `current = next_node`.

Когда `current` станет `None`, новая голова будет в `prev`.

### Сложность

Время:

```text
O(n)
```

Память:

```text
O(1)
```

### Ловушки

- Сначала поменять `current.next`, а потом пытаться через него идти дальше.
- Создавать новый список, если задача требует развернуть текущий.
- Не обработать пустой список.

## 4. Linked List Cycle

Источник: https://leetcode.com/problems/linked-list-cycle/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Дана голова односвязного списка. Нужно понять, есть ли в списке цикл.

Пример:

```text
1 -> 2 -> 3 -> 4
     ^         |
     |_________|

result: True
```

### Идея

Используется алгоритм Флойда: два указателя.

- `slow` идет на один шаг.
- `fast` идет на два шага.
- Если цикл есть, они встретятся.
- Если цикла нет, `fast` дойдет до `None`.

### Сложность

Время:

```text
O(n)
```

Память:

```text
O(1)
```

### Ловушки

- Не проверять `fast` и `fast.next` перед движением.
- Использовать `set`, если от тебя ждут решение без дополнительной памяти.
- Думать, что если `slow` и `fast` не встретились за пару шагов, цикла нет. Нужно идти до конца.

## 5. Проверка палиндрома

Источник: https://coderun.yandex.ru/problem/palindroming-check

Тип источника: `CodeRun`.

### Что спрашивают

На CodeRun дана строка из букв английского алфавита и пробелов. Нужно определить, является ли строка палиндромом.

Перед решением важно уточнить правило:
- учитывать пробелы или нет;
- учитывать регистр или нет.

На собеседовании это нормальный уточняющий вопрос.

### Идея

Классический вариант решается двумя указателями:
- `left` идет с начала;
- `right` идет с конца;
- если пробелы нужно игнорировать, указатели пропускают пробелы;
- символы сравниваются попарно;
- если нашлась разная пара, это не палиндром.

### Сложность

Время:

```text
O(n)
```

Память:

```text
O(1)
```

Если не создавать очищенную копию строки.

### Ловушки

- Не уточнить правила про пробелы и регистр.
- Сделать `s == s[::-1]`, когда хотят проверить умение работать двумя указателями.
- Создать много промежуточных строк в цикле.

## 6. Reverse Words in a String

Источник: https://leetcode.com/problems/reverse-words-in-a-string/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Дана строка со словами и пробелами. Нужно вернуть строку, где порядок слов обратный, но сами слова не развернуты. Лишние пробелы нужно убрать.

Пример:

```python
s = "  hello   from   yandex  "
# result: "yandex from hello"
```

### Идея

Простой вариант:
- разбить строку на слова;
- развернуть список слов;
- собрать обратно через один пробел.

Если требуют in-place для массива символов, подход другой:
- развернуть всю строку;
- потом развернуть каждое слово отдельно;
- убрать лишние пробелы.

### Сложность

Время:

```text
O(n)
```

Память:

```text
O(n)
```

Для обычного Python-решения через `split`.

### Ловушки

- Оставить лишние пробелы.
- Развернуть символы внутри слов.
- Не обработать строку из одних пробелов.

## 7. Вывод листьев BST

Источник: https://coderun.yandex.ru/problem/leaf-conclusion

Тип источника: `CodeRun`.

### Что спрашивают

По последовательности чисел нужно построить бинарное дерево поиска. Последовательность заканчивается `0`, сам `0` не добавляется. Нужно вывести все листья дерева в порядке возрастания.

Пример из CodeRun:

```text
Ввод:
7 3 2 1 9 5 4 6 8 0

Вывод:
1
4
6
8
```

### Идея

Сначала строится BST:
- если новое значение меньше текущего узла, идем влево;
- если больше, идем вправо;
- вставляем значение в первое свободное место.

Потом делается in-order обход:
- левое поддерево;
- текущий узел;
- правое поддерево.

Для BST такой обход дает значения по возрастанию. Если текущий узел не имеет детей, он лист, его нужно вывести.

### Сложность

Среднее время построения:

```text
O(n log n)
```

Худшее время построения:

```text
O(n^2)
```

Если дерево вырождается в цепочку.

Время обхода:

```text
O(n)
```

Память:

```text
O(h)
```

Где `h` - высота дерева. Это память на стек рекурсии.

### Ловушки

- Добавить завершающий `0` в дерево.
- Перепутать порядок обхода.
- Выводить все узлы, а не только листья.

## 8. Validate Binary Search Tree

Источник: https://leetcode.com/problems/validate-binary-search-tree/

Тип источника: `Yandex-tagged LeetCode`.

### Что спрашивают

Дано бинарное дерево. Нужно проверить, является ли оно корректным бинарным деревом поиска.

Пример:

```text
    2
   / \
  1   3

result: True
```

Контрпример:

```text
    5
   / \
  1   4
     / \
    3   6

result: False
```

### Идея

Главное: проверять нужно не только детей, а все ограничения от предков.

DFS получает границы:
- `low` - минимально допустимое значение;
- `high` - максимально допустимое значение.

Для левого ребенка:
- новая верхняя граница равна значению текущего узла.

Для правого ребенка:
- новая нижняя граница равна значению текущего узла.

Если узел нарушает границы, дерево не BST.

### Сложность

Время:

```text
O(n)
```

Память:

```text
O(h)
```

Где `h` - высота дерева.

### Ловушки

- Проверять только непосредственных детей.
- Разрешить одинаковые значения, если по условию BST строгий.
- Забыть, что ограничения идут от всех предков.
