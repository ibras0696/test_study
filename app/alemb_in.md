**Коротко:**
Alembic = инструмент миграций для БД при работе с SQLAlchemy.
Команды позволяют **создавать, применять и откатывать изменения схемы** (таблицы, колонки, индексы).

---

# 🔧 Базовый флоу (как это используется)

1. Меняешь модели в коде
2. Генерируешь миграцию
3. Применяешь её в БД

---

# 📦 Основные команды Alembic

## 1. Инициализация проекта

```bash
alembic init migrations
```

📌 Что делает:

* создаёт папку `migrations/`
* файл `alembic.ini`
* шаблон env.py

👉 Используется **1 раз** в проекте

---

## 2. Создание миграции

### 🔹 Авто (рекомендуется)

```bash
alembic revision --autogenerate -m "add users table"
```

📌 Что делает:

* сравнивает модели SQLAlchemy с БД
* генерирует diff (изменения)

👉 Требование:

* в `env.py` должен быть подключен `Base.metadata`

---

### 🔹 Ручной режим

```bash
alembic revision -m "custom change"
```

📌 Что делает:

* создаёт пустой файл миграции
* ты сам пишешь SQL/операции

---

## 3. Применение миграций

```bash
alembic upgrade head
```

📌 Что делает:

* применяет ВСЕ миграции до последней

---

### Частичный апгрейд

```bash
alembic upgrade +1
```

👉 применяет только одну миграцию

---

## 4. Откат миграций

```bash
alembic downgrade -1
```

📌 Что делает:

* откатывает последнюю миграцию

---

```bash
alembic downgrade base
```

👉 откат до нуля (всё снести)

---

## 5. Просмотр текущего состояния

```bash
alembic current
```

📌 какая версия сейчас в БД

---

```bash
alembic history
```

📌 список всех миграций

---

```bash
alembic heads
```

📌 последняя версия (если несколько веток)

---

## 6. Отметить миграцию без выполнения (⚠️)

```bash
alembic stamp head
```

📌 Что делает:

* говорит: "БД уже на этой версии"
* но SQL НЕ выполняет

👉 используется при:

* ручной настройке БД
* синхронизации окружений

---

# ⚠️ Важные нюансы (где ломаются проекты)

## ❌ Антипаттерны

* `create_all()` вместе с Alembic
  👉 ломает контроль схемы
  👉 **запрещено в проде**

* править старые миграции
  👉 нельзя после релиза
  👉 только новые миграции

---

## ⚠️ Autogenerate не идеален

Он НЕ видит:

* rename колонок (считает как drop + create)
* сложные изменения типов
* кастомные индексы/constraints

👉 нужно проверять руками

---

## ⚠️ Async стек (твой кейс)

Если используешь:

* FastAPI + async SQLAlchemy

👉 Alembic всё равно работает через sync engine
👉 это нормально

---

# 🧠 Как это выглядит в жизни

Ты добавил поле `email` в User:

1.

```bash
alembic revision --autogenerate -m "add email"
```

2.

```bash
alembic upgrade head
```

👉 БД обновилась, код и схема синхронны

---

# ➕ Плюсы / минусы

## ✅ Плюсы

* контроль версий БД
* откаты
* командная работа
* прод-готовый стандарт

## ❌ Минусы

* требует дисциплины
* autogenerate не 100% точен
* конфликты миграций в команде

# 🧩 Вывод

Alembic — **обязательный инструмент для production backend**.
Минимальный набор, который ты должен знать:

```bash
init → revision --autogenerate → upgrade → downgrade
```
